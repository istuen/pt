# 迁移：v9.0 → v9.1 — Profile 必须填 `### Modules`

## 背景

v9.1（[modules-to-profile 迁移](../designs/modules-to-profile.md)）把"聚合标题选择"的决定权从 Blueprint.modules 迁到 ProfileGroup.modules。Blueprint 退化为"插槽契约"（只声明有哪些聚合组 + inject + mode），Profile 通过 H2 段下的 `### Modules` 段声明本插槽聚合哪些 modName。

## 影响

升级到 v9.1+ 的项目，每个 Profile 的每个 H2 聚合组段下必须填 `### Modules`。否则编译产物为空 segment → footer 永远 `idle`。

## 检测

`scanProjectHealth()` 已在 `src/asset-health.ts` 实现 `missing-modules` 规则：

- **触发**：ProfileGroup.modules.length === 0（Profile 引用了 Blueprint 的某插槽但没填 `### Modules`）
- **严重程度**：error
- **检测时机**：`session_start` 末尾 + `/pt check` + `pt_check` tool
- **可见性**：
  - session_start：`[pt] 项目有 N errors + M warnings（运行 /pt check 查看详情）`
  - footer：末尾追加 `⚠ N issues`（健康问题染色）
  - `/pt status`：新 `pt health: N issues` 行

## 修复步骤

每个有问题的 Profile（`/pt check` 输出会列文件名）：

1. 打开 Profile（`.pt/assets/profiles/<name>.profile.md`）
2. 在每个 H2 聚合组段下加 `### Modules`，列出 modName

**modName 两种形态**（详见 `src/parse/profile.ts:parseModName`）：

- 段名：`Scene` / `Trigger` / `Rules` / `Flows` / `Checklists` / `User` / `Agent`
- 段.项：`User.user-profile` / `Agent.agent-role-architect`

**完整段名清单**（`KNOWN_SECTION_NAMES`）：Scene / Participant / Trigger / Rules / Flows / Checklists / User / Agent / Term

## 示例

修复前（v9.0 兼容写法，v9.1+ 编译空 segment）：

```markdown
## 会话背景
### Domains
- ysl-company
- fastener-industry
```

修复后：

```markdown
## 会话背景
### Modules
- Scene
- User
### Domains
- ysl-company
- fastener-industry
```

注意：原本在 Blueprint.yaml 的 `groups[].modules: [Scene, Participant]` 也已删除——Blueprint 不再带 modules 列表。

## 自动 fix（v2 范围）

`/pt check --fix` 计划在 v2 实现。当前 v1 只输出 `fix:` hint 提示用户手动改。
