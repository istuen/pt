## 4. TurnContext 使用图景

> ⚠ v1 只统计 compaction:clue-injected 是误读——那只记 session_compact 恢复线索。
> TurnContext 真实注入路径有 4 个，日志分散在不同事件：
> - pt_inject tool 调用（Agent 主动查手册详情）→ tool:call name=pt_inject
> - pt_doc tool 调用（含 start manual 设 lastTurnRef）→ tool:call name=pt_doc
> - session_compact 恢复线索 → compaction:clue-injected
> - session 启动恢复上次线索 → lastTurnRef:restored
> ⚠ sensor 盲区：tool:call 不记 input/action 参数，无法统计 pt_inject 调了哪个 domain。

### 4.3 TurnContext 使用率判断

- **Agent 主动调 pt_inject：32 次 / 18452 turn**
- pt_inject 调用率：0.1734%（每 100 turn 调 0.1734 次）

> 处置：切到该 profile 跑一次 session（或 `rm -rf .pt/cache/agent-contexts` 后逐个激活）→ 产物写入后再跑本脚本。

> **读法**：
> - 「被查次数 = 0」→ 该 trigger 一直摆在面前但**从没人查** → desc 可能没写清「什么时候该查它」
>   （对应 issue pt-trigger-relevance-signal §七：领域边界式 desc 在灰区任务上仅 16.4% 触发）
> - 「被查次数 > 0」→ 有效信号

> 🔴 **本表的「被查 = 0」暂不可信**：这批日志里有 32 次 pt_inject
>   **没带 `input.domain`**（日志早于 Layer 1 F1.2）→ 查了但归因不到具体 domain。
>   → 本表把那些 domain 记成「被查 0」是**测量假象**，不是真的没人查。
>   → **等 F1.2 之后的日志积累够了再看本表**（或只统计 F1.2 之后的 session）。

> ⚠ **口径边界**：本节是**相关性**不是**因果**——被查不等于「因为这条 trigger 才查的」，
>   也不等于「没查就是 desc 写得不好」（可能是该 session 的任务本来就不该查）。
>
> ⚠ **粒度边界**：曝光侧按 **profile** 统计（不是按 session）——因为「某 profile 的每个 session 都看得到同一份 trigger-index」。
>   故「曝光 profile 数」列恒为 1 时不代表只有 1 个 session 看过它。
>
> ⚠ **可用性边界（重要）**：编译产物目录**每个 profile 只留最近一次编译的那份**
>   （Pt 的 prune 机制 + 同名覆盖）——所以：
>   - 本表只覆盖「当前缓存目录里还有产物」的 profile；
>   - 若某 profile 近期被别的 profile 覆盖/清理过，它的触发信号就**不在表里**
>     （表里看不到 ≠ 没被查过，只表示「曝光侧无数据」）；
>   - **要完整统计，需在目标 profile 活跃时跑本脚本**（或先 `rm -rf .pt/cache/agent-contexts` 强制各 profile 重编译）。

## 10. 观察与初步解读

> **本节是数据解读，不是结论——待你确认后定正式解读。**

### 待确认的观察点

1. **Profile 使用分布**——哪个 Profile 激活最多？是否符合预期工作场景分布？
2. **注入增量**——平均注入 X 字符/tokens 是否在合理范围（不超 LLM context budget）？
3. **TurnContext 命中**——哪些 Domain trigger 命中最多？是否说明这些知识 Agent 最常需要？有没有该触发但没触发的？
   （v2：§4.4 给 Domain 级频率，§4.5 给「曝光 vs 查阅」——被查 0 次的 trigger 就是「摆在面前没人查」清单）
4. **工具使用**——Agent 调 pt 工具的频率 vs 调 bash/read/edit 的频率，比例如何？
5. **缓存命中**——hit rate 反映资产稳定性。
6. **配置错误**——Profile 引用未知 Blueprint 是否当前仍坏（vs 历史遗留已修）？
7. **时间趋势**——使用量是增长、平稳还是衰退？
8. **trigger 采用率**（v2 新增）——§4.5 里「被查 = 0」的 trigger 条目，是不是 desc 没写清「什么时候该查它」？
   （对应 issue pt-trigger-relevance-signal §七：领域边界式 desc 在灰区任务上仅 16.4% 触发；
   §七之三 §7.8.4.3：效应只在「desc 的词与任务描述的词对齐」时出现）
